1. Introduction

1.1FreeFile is an Android dual-pane file manager built with Kotlin and Jetpack Compose. It combines local, Root and Shizuku file access with network storage, a terminal, scripting, archive handling, encryption, and reverse-engineering tools.

1.2A unified Virtual File System (VFS) abstraction lets the same copy, move, rename, and delete operations run on local scoped storage, Root Shell, Shizuku, inside archives, and on remote locations such as SMB, FTP, WebDAV, and S3.

1.3The goal is to deliver desktop-class file management efficiency on a phone while keeping the interface clear, operations predictable, and destructive actions guarded by confirmation and undo.

2. Getting Started

2.1On first launch, a feature dialog lets you read the User Agreement, Privacy Policy, this Help document, and the About page. Tap “Agree and continue” to enter the main interface.

2.2Recommended setup order:

  1. Grant “All files access” (on Android 11 and later this must be enabled manually in system settings) for shared-storage browsing and modification.
  2. To access protected directories such as /data and /system, install and authorize Shizuku, or configure Root on your device.
  3. Open Settings to review the access-engine priority, file-size calculation, language, and search-index options.

2.3The main screen uses a left and right pane, each with multiple tabs. Touch a pane to make it active; bottom-toolbar actions such as copy, paste, and delete apply only to the active pane.

2.4The right pane can be temporarily hidden or shown from the top bar, making it easy to switch between single-pane and dual-pane layouts. The two panes can also be swapped with one tap.

3. File Management

Dual pane & tabsBoth panes browse independently; tab sessions persist and restore your last location after a restart.
Complete operationsCreate (including multi-level paths like a/b/c), copy, cut, paste, rename, batch rename, and delete.
Recycle binDeleted items go to the recycle bin by default and can be restored or purged; permanent deletion is available after confirmation.
Multi-selectSelect all, invert selection, or range-select by long press, then batch-process from the action panel.
PropertiesView path, size, timestamps, and permissions; compute directory sizes and persistently display MD5 / SHA-256 for files.
Navigation aidsBreadcrumbs, jump-to-path, bookmarks, recent folders, recent files; every list has a fixed .. entry for the parent directory.
Three viewsList, grid, and large-icon views with sorting by name, size, type, or time, ascending or descending.
Fine-grained filtersFilter by folders, images, videos, audio, archives, documents, code, APKs, and more, with a hidden-files toggle.

3.1When copying, moving, or extracting encounters a name conflict, choose “Overwrite / Skip / Keep both” and apply the choice to the whole batch to avoid repeated prompts.

3.2File-size calculation is disabled by default to keep large directories fast. Enable it in Settings, or compute a directory size manually from the properties panel when needed.

3.3The access engine automatically probes in the order Root > Shizuku > local scoped storage and remembers the mapping from path prefix to engine. You can also force “Auto / Root first / Shizuku first / Local only” in Settings.

4. Search & Indexing

4.1Search supports configurable recursion depth (current folder, a specified number of levels, or unlimited), plus wildcards * ?, regular expressions, exact match, and case sensitivity.

4.2Combine size, modification-time, and content filters, then jump to a result's folder or run batch actions directly from the results.

4.3With “Search index cache” enabled, the app builds an index in the background for near-instant repeated searches. The index can be disabled, cleared, or rebuilt in Settings. It is stored only on your device and never uploaded.

5. Compression & Extraction

5.1Supported formats: zip, jar, apk, 7z, tar, tar.gz, tgz, tar.bz2, tar.xz, rar4, rar5, gz, bz2, and xz.

5.2Browse inside archives without extracting: the xxx.zip#/internal/path syntax maps an archive's internal folders so you can view, copy, or extract individual files as if they were ordinary directories.

5.3Encrypted ZIP files prompt for a password during extraction; a wrong password or damaged archive produces a clear error and no incorrect output. Archive passwords and the separate “File encryption” password are independent.

5.4When compressing, choose the target format and compression level. ZIP additionally supports a password and split-volume size in MB (0 means no splitting). The destination file extension follows the selected format automatically.

5.5Large compression or extraction jobs run as background tasks with progress reporting and can jump to the output folder when finished.

6. File Encryption & Decryption

6.1Encryption protects a single file and produces an originalname.cry file. To restore the original name and contents, select the .cry file and enter the password.

6.2Encryption is streamed to avoid loading large files into memory. The password is used only to derive the key and is never stored in any form.

6.3If the password is wrong or the file has been modified, authentication fails and no plaintext is produced. Keep your password safe; it cannot be recovered if lost.

6.4You may delete the source file after encryption. If system permissions prevent deletion, the app will ask you to remove it manually.

7. Network Storage & LAN Sharing

7.1Supports WebDAV, FTP, SMB2/3, and S3 (compatible with endpoints such as Alibaba OSS), all using the remote:// path syntax. Locations can be saved and edited with SSL, domain, bucket, and custom endpoint options.

7.2LAN sharing uses NanoHTTPD and mDNS to discover nearby devices and transfer files without mobile data, with a record of received files.

7.3Enable sharing only on trusted private networks. Do not expose the service on public Wi-Fi, and never share remote-storage credentials with others.

8. Terminal & Script Engine

8.1The terminal is built on Termux terminal-emulator with a real PTY and VT100 support. It offers multiple sessions, normal and Root modes, and a customizable interpreter path such as /system/bin/bash.

8.2Opening the terminal from a file list can automatically change to the target directory and list the selected files. The terminal runs in its own task stack so you can switch freely with the file UI.

8.3The script engine includes Lua (LuaJ) and can invoke a Python interpreter installed on the device. File APIs include freefile.list / read / write / copy / delete / mkdir / rename / exists / log.

8.4Built-in sample scripts cover listing directories, storage information, finding large files, batch-rename previews, directory-size calculation, and removing empty folders, and serve as references for your own scripts.

9. Text & Rich Text Editing

9.1The text editor supports search, replace, replace-all, regex, whole-word matching, case sensitivity, line numbers, jump-to-line, font-size adjustment, and multiple encodings.

9.2Files larger than 1 MB enter a “large-file smooth mode” with truncated loading to avoid lag. For full editing, consider processing the file on a computer or splitting it first.

9.3The rich text editor supports HTML, Markdown, and plain text with format conversion and hyperlink insertion.

10. Reverse-Engineering Tools

10.1The “Tool Tray” includes APK tools (Acode, APKToolM). It can pass the current file directly to a tool and follow an “extract → install → launch” workflow.

10.2The “APK Launcher” parses the package name, launcher activity, and version of an uninstalled APK, and lets you customize the launch Intent (Action, Category, Data, Extras, and window flags).

10.3“VirtualBox run-without-install” uses a virtual app container (Bcore) to import and run an APK without installing it into the system.

10.4These tools are intended only for study, personal file processing, and analysis of apps you own. Comply with local laws and the target software's license. Do not use them to crack, tamper with, or infringe on others' rights.

11. Browser, Media & Document Viewers

11.1The built-in browser supports tabs, an address bar, search, bookmarks, and in-page downloads. Uploads triggered by a page accept any file type and multiple selection. HTTP downloads go to the system downloader, while blob / data links are saved through an in-app bridge, with real-time progress shown at the bottom of the page.

11.2Images support pinch-to-zoom, double-tap zoom, and panning. Video and audio use Media3 ExoPlayer, and media files can be swiped left and right within the same viewer.

11.3The PDF viewer provides page jumping, zooming, sharing, and file details. If a file is deleted in a viewer, the result is returned to the main screen and the current folder refreshes.

12. AI File Management Assistant

12.1The “File Management Agent” in the side drawer provides natural-language-driven file operations and Q&A. All file facts come from tool calls; the model does not invent file contents.

12.2Every write operation follows a “preview → confirm → execute → undo” cycle, and batches over 10 files require a summarized confirmation. Specific actions can be pre-authorized in Settings.

12.3Multiple sessions and tabs, conversation persistence, renaming, and an independent context per conversation are supported. Third-party MCP servers can be connected, and HTTP request logs can be recorded.

12.4Sensitive directories, vaults, and encrypted containers are not indexed or auto-scanned by default. AI-generated content saved as a file also goes through the standard write-confirmation flow.

13. FAQ

Q1Why can't I see Android/data or obb?
Make sure “All files access” is granted and the access engine is set to Auto, Root, or Shizuku. With ordinary scoped storage on Android 11 and later, some system directories are not directly accessible.

Q2Shizuku is installed but still shows no permission.
Start the Shizuku service in the Shizuku app and authorize FreeFile. On some devices, Shizuku must be restarted after every reboot.

Q3Folders open slowly or size shows “—”.
File-size calculation is off by default. Enable it in Settings, or use the properties panel only for folders you need to measure to avoid scanning very large trees.

Q4The archive reports a wrong password.
Confirm the archive is actually encrypted and that the password's case and characters match exactly. The app's file-encryption password is unrelated to ZIP archive passwords.

Q5Where did deleted files go?
By default they go to the recycle bin, reachable from the side drawer, where you can restore or purge them. Permanently deleted files cannot be recovered through the app.

Q6The terminal shows no output or the keyboard misbehaves.
Make sure the session was created and has not been reclaimed by the system. Try a new session, switch between normal and Root modes, or change the interpreter path in Settings.

Q7How do I change the language?
Go to Settings → Language and choose Simplified Chinese or English; the change takes effect immediately. Documents in the Gallery can also switch between Chinese and English independently.

Q8Why isn't a web download in the Downloads folder?
HTTP downloads are saved by the system downloader to the public Downloads folder; blob / data content is written to Downloads by the app. Under scoped storage, files may instead be placed in the app-specific external directory.
